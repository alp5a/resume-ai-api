# Resume AI API

A small retrieval-based Q&A system for a resume. A FastAPI backend indexes a
resume (from `data/sample_resume.json`) into a ChromaDB vector store using
sentence-transformer embeddings, and answers natural-language questions by
retrieving the most relevant section(s). A Streamlit app provides a simple
chat UI on top of the API.

## Project structure

```
resume-ai-api/
├── app/
│   ├── __init__.py
│   ├── main.py          # FastAPI app + endpoints
│   ├── database.py       # ChromaDB indexing/query helpers
│   ├── models.py         # Pydantic request/response models
│   └── resume_data.py    # Loads resume JSON, builds text chunks
├── frontend/
│   └── streamlit_app.py  # Streamlit chat UI
├── data/
│   └── sample_resume.json
├── requirements.txt
├── Dockerfile
├── .gitignore
└── README.md
```

## Setup

```bash
# Clone the repo, then from the project root:
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate

pip install -r requirements.txt
```

## Running locally

**Terminal 1 — backend:**

```bash
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

You should see something like:

```
✅ Indexed 12 resume chunks
INFO:     Application startup complete.
```

Visit `http://localhost:8000/docs` for interactive API docs.

**Terminal 2 — frontend:**

```bash
streamlit run frontend/streamlit_app.py
```

This opens `http://localhost:8501` in your browser.

## API endpoints

| Method | Path          | Description                              |
|--------|---------------|-------------------------------------------|
| GET    | `/`           | Basic info / links                       |
| GET    | `/health`     | Health check + number of indexed chunks  |
| GET    | `/api/resume` | Full raw resume JSON                     |
| POST   | `/api/query`  | Ask a question about the resume          |

Example request:

```bash
curl -X POST http://localhost:8000/api/query \
  -H "Content-Type: application/json" \
  -d '{"question": "What AI/ML experience do they have?", "top_k": 3}'
```

## Using your own resume

Replace `data/sample_resume.json` with your own data, following the same
structure (`personal_info`, `summary`, `skills`, `experience`, `projects`,
`education`, `certifications`). Restart the backend to re-index.

## Running with Docker

```bash
docker build -t resume-ai-api .
docker run -p 8000:8000 resume-ai-api
```

The Streamlit frontend isn't included in the Dockerfile (it's meant to run
locally against the API), but you can point it at a containerized backend by
setting `RESUME_API_URL` before running it:

```bash
RESUME_API_URL=http://localhost:8000 streamlit run frontend/streamlit_app.py
```

## Notes

- The vector store is in-memory by default (rebuilt on every backend
  restart). Swap `chromadb.Client()` for
  `chromadb.PersistentClient(path="./chroma_db")` in `app/database.py` if you
  want it to persist between runs.
- Answers are extractive (built from the best-matching resume chunk(s)),
  not generated by an LLM — no API key required. Wiring in an LLM call
  (e.g. OpenAI or Anthropic) to synthesize the final answer from retrieved
  chunks would be a natural next step.
